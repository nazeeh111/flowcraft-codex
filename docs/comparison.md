# Comparison and implementation decisions

Inspected 2026-10-21. This is a bounded comparison of relevant public projects, not an exhaustive census. Source observations, paper claims and local verification are distinguished below. No provider pipelines or model benchmark evaluations were run locally.

## Selected evidence

| Project | Evidence and actual mechanism | Decision for this integration |
|---|---|---|

Reference retrieval, planning, styling, rendering and iterative critique; API-dependent runner defaults to multiple candidates. | Retain its scientific visual workflow as in-session reasoning passes. One candidate by default, actual rendered-image review, no provider credential setup. |

| [Paper2Any](https://github.com/OpenDCAI/Paper2Any) | Current README identifies the repository as a legacy snapshot; newer hosted Nexus Office capabilities are excluded. | Route actual PPTX/document deliverables to installed artifact tools; do not import an office platform for figure export. |

Verify formulas and endpoints; avoid assuming editable semantics from a file format. |
| [DeTikZify](https://github.com/potamides/DeTikZify) | Public image/sketch-to-TikZ approach with iterative graphics-program search. | Optional TikZ route when math and existing TeX tooling justify it. Models and hardware support are not installed or locally verified here. |
| [StarVector](https://github.com/joanrod/star-vector) | Public semantic SVG-generation models; official examples use CUDA and document natural-image limitations. | Prefer real text and semantic SVG primitives. ## Combined design

The installed skill uses a single Codex session and existing execution tools. It keeps reference-guided planning, stable semantic objects, source-to-element grounding, a multi-turn requirements ledger, local SVG/PNG/PDF exports, data-derived quantitative plots and bounded rendered-image critique. It does not introduce a second agent framework, API service, model download or background process.

PNG validation catches structural faults and resource limits. PDF tests establish basic vector output and physical dimensions for tested content. Neither establishes general SVG compatibility, correct science or superior aesthetics. Retained source and targeted visual review remain necessary.

Alternative implementations exposed real gaps in the first version: cross-turn requirement retention, clear vector/hybrid distinctions, portable dependency installation and a built-in vector PDF path. Independent review additionally found unbounded projected raster height, a relative CSS-resource check gap, and a missing training-update path in the demo. These were corrected and added to regression checks.
